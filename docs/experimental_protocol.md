# Experimental protocol and reproducibility checklist

This document separates the study design reported in the project summary from items that still need verification against the actual runs.

## Study design reported by the authors

- Task: multilabel, context-aware emotion recognition on EMOTIC.
- Visual/language pipeline: InstructBLIP EVA-ViT-g visual encoder and Q-Former, with contextual descriptions generated by LLaVA.
- Repeated runs: five seeds per reported configuration.
- Selection: validation data is used for configuration selection; the official test split is evaluated after selection.
- Phase A: baseline reproduction and additional person/region/bounding-box geometry inputs.
- Phase B: augmentation, a longer schedule, test-time mirroring, and partial encoder fine-tuning.
- Phase C: GEQ, alternative multilabel heads, GEQ component ablations, and LoRA adaptation.
- Reported official test population: 7,279 annotated persons.

## Annotation-aggregation discrepancy — resolve before publication

The current project materials are not consistent about the annotation aggregation rule:

- The manuscript abstract describes test labels as pooling the **median of three annotators**.
- Comments in the Phase A notebook describe the test categories as the **union over three annotators** and describe validation labels as rebuilt to mirror that protocol.

These operations are not interchangeable. Do not assume one is a synonym for the other. Inspect the original EMOTIC annotation representation and the exact preprocessing/evaluation functions, then establish the intended rule. Update the manuscript, notebook comments, cached labels, and README together. Record the rule precisely (including how per-annotator categories are converted into the target vector) before claiming exact test-protocol alignment.

## Required run manifest

For each configuration and seed, retain at least:

- Phase and configuration identifier.
- Random seed and deterministic settings, if enabled.
- Dataset/version identifiers and split-file hashes.
- Annotation aggregation implementation/version.
- Preprocessing and input feature definitions.
- Model checkpoint identifiers and hashes where practical.
- Python, PyTorch, Transformers, torchvision, CUDA, driver, and GPU versions.
- Optimizer, learning-rate schedule, batch size, epoch/step count, loss, and checkpoint-selection rule.
- Whether encoder/Q-Former parameters are frozen or trainable and the exact LoRA target modules/rank/scaling/dropout.
- Per-seed validation and test mAP; for the final test, keep the selection procedure fixed before evaluation.
- Logs and checkpoint paths (paths can be local; do not commit large artifacts).

## Statistical reporting

- Report individual seed values and the aggregation convention (sample SD or population SD).
- For paired comparisons, report the per-seed paired differences and the named statistical test.
- State the confidence-interval procedure and whether the interval is for a mean difference.
- For non-inferiority, state the margin, null/alternative hypotheses, confidence level, and decision rule before inspecting outcomes.
- Use mAP percentage points consistently; distinguish them from relative percent changes.

## Pre-publication checklist

- [ ] Resolve the median-versus-union annotation discrepancy.

- [ ] Verify that all five seeds per reported configuration are present and correctly paired.
